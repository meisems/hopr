# Hopr – Hop Across Chains

A cross-chain trading bot that lives in **Telegram**: it trades with encrypted Hopr wallets after the user confirms a fresh quote, and tracks every token those wallets hold across all 7 chains. The website is a read-only viewer — scan tokens, charts, trending and launch radar — whose **Trade on Telegram** buttons open the scanned token straight in the bot (`t.me/<bot>?start=t_<address>`). Any token on any of the 7 chains can be bought with any chain's coin — e.g. 1 SOL of a Base token, 1 ETH of a Solana token, or 1 NEAR of either.

## 🚀 Deployment (Cloudflare Pages + Workers)

### Prerequisites
- Node.js 18+
- Cloudflare account with Pages & Workers enabled
- Wrangler CLI: `npm install -g wrangler`

### Frontend (Cloudflare Pages)
```bash
# Install dependencies
npm install

# Build
npm run build

# Deploy to Pages
npx wrangler pages deploy dist --project-name=hopr
```

### Backend (Cloudflare Workers)
```bash
# Deploy worker
npx wrangler deploy

# Create D1 database
npx wrangler d1 create hopr-db

# Create KV namespace
npx wrangler kv:namespace create CACHE
```

### Environment Variables
Set these in Cloudflare Dashboard → Workers → Settings → Variables:
- `ENCRYPTION_KEY` – AES-256-GCM key for wallet encryption
- `LIFI_API_KEY` – LI.FI API key for cross-chain routing. **Required in production**: without a key every user shares the worker's anonymous LI.FI quota and trading stops once it runs out
- `LIFI_INTEGRATOR` – optional LI.FI integrator override; defaults to `hopr`
- `TELEGRAM_BOT_TOKEN` – token generated by @BotFather
- `TELEGRAM_WEBHOOK_SECRET` – random secret used to authenticate Telegram webhook requests
- `VITE_API_URL` (website build) – URL of the deployed worker; the website reads the bot link from `/api/config` and launch radar from `/api/launchpads/pools`
- `HOPR_INTENTS_FEE_ACCOUNT` (worker) – Hopr's NEAR account. It receives the 0.5% / 1% fee on NEAR Intents routes and on Ref Finance (NEAR ↔ NEAR) swaps; Without it, NEAR routes charge no Hopr fee and earn no referral rewards. The account must exist on NEAR mainnet.
- `ONECLICK_JWT` (worker secret, recommended) – NEAR Intents 1Click API key. Default authenticated terms split the submitted app fee 50/50. Without a key HOPR keeps the submitted fee and 1Click adds 0.25% on top
- `TELEGRAM_BOT_USERNAME` (worker, optional) – bot username for invite links (`t.me/<bot>?start=ref_<code>`); read from Telegram's getMe when unset
- `ALCHEMY_API_KEY` (worker secret, recommended) – one key gives keyed RPCs for Base, Arbitrum, BNB Chain and Solana, plus EVM token discovery for 💼 Portfolio
- `HELIUS_API_KEY` (worker secret, recommended) – keyed Solana RPC for reads, token discovery and sending transactions (only a couple of public Solana RPCs allow token discovery)
- `RPC_BASE`, `RPC_ARBITRUM`, `RPC_BSC`, `RPC_ROBINHOOD`, `RPC_ARC`, `RPC_SOLANA` (worker secrets, optional) – full keyed RPC URLs per chain (comma-separate several); they win over the provider keys. Robinhood and Arc have no Alchemy default, so set these for reliable trading there
- `VITE_RPC_BASE`, `VITE_RPC_ARB`, … (website build, optional) – keyed RPCs for the website's scanner
- `ADMIN_TOKEN` (worker secret) – bearer token for `GET /api/admin/referral-payouts` and `POST /api/admin/referral-payouts/paid`
- `REFERRAL_MIN_PAYOUT_USD` (worker, optional) – minimum claim, default 5
- `VITE_TELEGRAM_BOT_URL` (dashboard build, optional) – public bot link such as `https://t.me/YourBot` for the website's **Trade on Telegram** buttons; when unset it is read from the worker's `/api/config`
- `ENVIRONMENT` – `production` or `staging`
- `NEAR_RPC_URL` (secret, recommended) – keyed NEAR mainnet RPC endpoint (comma-separate several). Free public NEAR RPCs are heavily rate limited (and `rpc.mainnet.near.org` is deprecated); they are used only as fallbacks after this URL

Every key is listed in [`.dev.vars.example`](.dev.vars.example). After deploying, `GET /health` reports which keys are configured (true/false only, never values).

**How RPCs are used:** every read (balances, portfolio, scans) and every transaction goes through one ordered list per chain — keyed endpoints first, then verified public backups. Reads are hedged across endpoints so one slow RPC never stalls the bot; a transaction is only sent through an endpoint that just answered with the right chain id, and Solana transactions are also rebroadcast to two backups so they land.

After deploying the Worker, set its two Telegram secrets and register its webhook, slash-command suggestions, and command menu:

```bash
# Enter the token without echoing it or storing it in shell history.
read -rsp 'Telegram bot token: ' TELEGRAM_BOT_TOKEN; echo; export TELEGRAM_BOT_TOKEN
# Generate a secret and store both values as Cloudflare Worker secrets.
export TELEGRAM_WEBHOOK_SECRET="$(openssl rand -hex 32)"
printf '%s' "$TELEGRAM_BOT_TOKEN" | npx wrangler secret put TELEGRAM_BOT_TOKEN
printf '%s' "$TELEGRAM_WEBHOOK_SECRET" | npx wrangler secret put TELEGRAM_WEBHOOK_SECRET

# Use the same secret for the local registration script and Cloudflare Worker.
export TELEGRAM_WEBHOOK_URL='https://your-worker.workers.dev/telegram/webhook'
npm run telegram:configure
```

The setup script calls Telegram's Bot API to register the webhook for messages and button callbacks, publish the bot commands, set the bot's profile description and "What can this bot do?" intro, and set the menu button to the command list (this also replaces an old Mini App button). It is safe to rerun after deploying. Keep the token and webhook secret out of source control and logs.

For persistent per-chat addresses and preferences, create a Cloudflare KV namespace (for example, `npx wrangler kv namespace create TELEGRAM_STATE`) and bind it to the Worker as `TELEGRAM_STATE` (Workers & Pages → your Worker → Settings → Bindings → Add → KV namespace). If deployments are managed by `wrangler.toml`, also add the returned namespace ID under a `[[kv_namespaces]]` entry with `binding = "TELEGRAM_STATE"`. Custodial wallets and confirmed trading require D1 migrations and ENCRYPTION_KEY. Never send a seed phrase in chat. Without this binding, `/wallet <address>`, `/balances <address>`, and token lookup work immediately, while saved-wallet and preference commands explain that persistence has not been configured.

## 🎯 Features

### Auto Chain Detection
- Paste any contract address → system detects chain automatically
- Base58 → Solana SPL Token detection
- 0x... → Multi-chain EVM probing (DexScreener + RPC fallback)
- DexScreener is raced against a single GeckoTerminal cross-network search; the deepest pool wins and its venue is named (Flap, Four.meme, Pump.fun, Clanker, Uniswap, PancakeSwap, Aerodrome…)
- On-chain reads race up to six verified backup RPCs per chain, so one slow or dead RPC never stalls a scan
- Launch radar tracks Flap (live from its on-chain launch events on BNB, Robinhood and Base), Four.meme, Clanker, Bankr, Bags, Meteora DBC, Pump.fun and more, plus Uniswap, PancakeSwap and Aerodrome pools

### Trading status
- Telegram Buy/Sell buttons fetch a fresh LI.FI quote and show a Confirm and submit button.
- Only the explicit confirmation signs and submits the stored, 90-second quote.
- A **0.5% platform fee** is included on every LI.FI swap quote using the `hopr` integrator. The fee wallet must be configured in the LI.FI Partner Portal.
- ✏️ **Buy X** takes any amount; with NEAR as the funding chain (/settings), EVM and Solana tokens are bought through NEAR Intents plus a ▶️ Continue step.

### 💼 Portfolio tracking
- `/portfolio` (or 💼 Portfolio) lists every token the active wallet holds on all 7 chains, grouped by chain with USD values and 24h change; tap a token to open its trading panel and sell
- Fast by design: one Multicall3 call per EVM chain reads the native coin plus every tracked token; Solana token accounts and FastNEAR's index list every SPL / Token-2022 / NEP-141 token; DexScreener prices 30 tokens per request. A full 7-chain portfolio typically loads in under 2 seconds
- Tracked automatically: every token you buy or open in the bot, plus EVM tokens Alchemy finds (with `ALCHEMY_API_KEY`). Untracked tokens need a real market to show, which hides airdropped spam and dust
- If a chain's RPCs are down, its last known balances are shown and labelled
- Token cards show what you hold of the token and how much you can pay with

### Fees
- **0.5% on trades, 1% on bridges**, charged once per trade: LI.FI integrator fee (`hopr`), NEAR Intents app fee, or an `ft_transfer` of 0.5% of the input inside the Ref Finance swap transaction
- Multi-step routes (e.g. NEAR → ETH → a Base token) charge the fee on step 1 only; later steps are fee-free

### Any token, paid with any chain
- EVM ↔ Solana (e.g. 1 SOL → a Base token, 1 ETH → a Solana token): one LI.FI transaction
- NEAR ↔ NEAR: Ref Finance
- NEAR ↔ tokens NEAR Intents lists (native coins, USDC, some majors): one NEAR Intents deposit
- NEAR ↔ any other token: planned as steps through a hub coin — NEAR → ETH on Base (Intents) → token (LI.FI), or token → wNEAR/ETH → … — each step sized from what the previous one actually delivered. In the bot, step 2 is one **▶️ Continue** tap
- In the bot, **every supported chain pays for every token**. NEAR tokens bought with SOL, ETH (Base, Arbitrum, Robinhood) or BNB go through NEAR Intents into NEAR, then Ref Finance; Arc (not on NEAR Intents) first hops to ETH on Base with LI.FI. Token cards have Pay-with buttons for NEAR, SOL and Robinhood ETH; any other chain is picked in /settings

### Referrals
- Referrers earn **25% of HOPR fee revenue after the routing provider share**. Under default authenticated 1Click terms, a 0.5% trade fee splits into 0.25% for 1Click and 0.25% for HOPR. A referred trade pays 0.0625% of volume to the referrer, leaving HOPR 0.1875%. For a 1% bridge, the corresponding amounts are 0.5%, 0.5%, 0.125%, and 0.375%. Without a referral HOPR keeps its entire share
- **Telegram only**: invite links are `t.me/<bot>?start=ref_<code>`, shown with earnings and claims in the bot's `/referral` (🎁 Refer & Earn). First link wins; no self-referrals. The website has no referral page
- A Telegram user is one referral identity (`tg:<id>`). Bot trades with the Hopr wallet are credited server-side
- Every trade is verified before it earns: LI.FI status API (Hopr integrator, sender, integrator-fee split), 1Click status (refund address, deposit transaction, app fee, and saved quote-time agreement), or the NEAR transaction itself for Ref swaps
- Claims above the minimum create USDC payout requests to the owner's wallet (Telegram users: their Hopr EVM wallet); operators list and mark them paid through the admin endpoints
- Requires migrations `0005`, `0006`, and `0007_intents_fee_policy.sql`. Missing LI.FI splits or historical 1Click agreements stay uncredited pending reconciliation. Existing credited balances are not rewritten: reconcile older payouts against provider statements before paying them. Custom 1Click partner terms require updating the accounting policy before use

### Wallets
- Each Telegram user has up to **10 Hopr wallets** (EVM + Solana + NEAR), managed in the bot: 💳 Wallets → 🔁 Switch wallet, 📦 New wallet, 📥 Import, 🔑 Export keys, 🗑 Delete (the active wallet only). `/start` creates the first one
- `/importkey evm|solana <key>` adds the key as a **new active wallet** (with fresh keys for the other chains), so an existing — possibly funded — key is never overwritten
- Every wallet also has a NEAR implicit account (64-hex id derived from an ed25519 key); keys are AES-256-GCM encrypted
- Never send private keys or seed phrases in a group

### Telegram Bot
- `/start`, `/help` – Welcome and help, with inline navigation buttons
- `/swap <amount> <from> <to>` – NEAR swaps via Ref Finance (e.g. `/swap 1 near usdc`); shows a quote with minimum received and one-time storage fees, then signs only after **Confirm swap**
- NEAR token addresses (`token.near` or 64-hex ids) open a market card with Buy 0.5 / 1 / 5 NEAR (or presets in SOL / ETH / … when paying from another chain) and Sell 25/50/100% (sized from the live token balance)
- `/importkey near <ed25519:key> [account.near]` – import a NEAR key; named accounts are verified on-chain to hold it as a full-access key, and an existing funded NEAR wallet is never overwritten
- `/wallet` and `/balances` – Native balances of your active Hopr wallet; 💳 Wallets switches, creates, imports, exports and deletes wallets (up to 10)
- `/portfolio` – Every token you hold on all 7 chains with live USD values
- `/settings` – Set and view a per-chat funding-chain and slippage preference
- Send a token address – Look up market information from DexScreener
- Telegram's native command suggestions and menu button are configured by `npm run telegram:configure`
- Telegram trades support native funding, token approvals, signing, and submission after explicit quote confirmation

## 🔒 Security

- Private keys encrypted with AES-256-GCM
- Encryption keys stored in Cloudflare Workers secrets
- Keys decrypted in-memory only during transaction signing
- No keys ever logged or transmitted unencrypted
- CORS headers restrict API access

## 📊 API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| POST | `/telegram/webhook` | The Telegram bot (secret-token authenticated) |
